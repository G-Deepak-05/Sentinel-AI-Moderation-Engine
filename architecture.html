Sentinel-AI Moderation Engine System Architecture
Shared Data Store
Request Lifecycle
①
Client POSTs text → POST :8081/api/v1/moderate · Gateway generates UUID, normalizes text, publishes Spring Event
②
KafkaProducerService sends moderation-requests · RequestEventListener saves ModerationRequest to PostgreSQL · Client gets 202 Accepted immediately
③
Inference Worker AIOKafkaConsumer picks up message → Toxic-BERT runs inference → max score across 4 labels → ALLOW / FLAG / BLOCK verdict
④
AIOKafkaProducer publishes result to moderation-results · Inference Worker also writes scores to PostgreSQL directly
⑤
ActionKafkaConsumerService saves ModerationResult to DB · If action ≠ FLAG → WebhookService fires POST to webhook-receiver:8080
⑥
Dashboard polls /api/stats + /api/activity from PostgreSQL · FLAG items surface in ReviewQueue for human moderators · Full audit trail preserved
